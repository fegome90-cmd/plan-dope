# Branch Review

## Purpose
Run `reviewctl` with a deterministic flow that avoids `UNKNOWN` static states and inconsistent reports.

## Source of Truth (non-negotiable)
- Canonical verdict source: `_ctx/review_runs/<run-id>/final.json`
- Human-readable companion: `_ctx/review_runs/<run-id>/final.md`
- Any custom summary/handoff must mirror `final.json`.

## Preparation Phase (required before any `run`)
Work in the target repository root and keep the whole review flow in the same shell session so exported variables remain available.

```bash
pwd
git rev-parse --show-toplevel
REVIEW_CLI="/Users/felipe_gonzalez/Developer/branch-review/mini-services/reviewctl/src/index.ts"
command -v bun
command -v jq
[ -f "$REVIEW_CLI" ] && echo "REVIEW_CLI_OK" || echo "REVIEW_CLI_MISSING"
[ -n "$REVIEW_API_TOKEN" ] && echo "REVIEW_API_TOKEN_OK" || echo "REVIEW_API_TOKEN_MISSING"
mkdir -p apps/pae-wizard/outputs/reviewctl
```

Read first if present:
- `docs/reviewctl-agent-guide.md`
- `docs/reviewctl-quick-reference.md`

Do not start `run` until these are true:
- target repo root confirmed
- `bun`, `jq`, and the `REVIEW_CLI` path resolve successfully
- `REVIEW_API_TOKEN` exists in the current shell
- output directory `apps/pae-wizard/outputs/reviewctl` exists

## Project Gate Profile (optional)
Read `.reviewctl/project-gates.json` if present. Defaults when missing:
- `frontend.enabled=false`
- `frontend.runner="vercel-browser-agent"`
- `frontend.blocking=false`
- `statics.biome_mode="changed-files"`
- `statics.ruff_mode="changed-files"`
- `statics.pytest_mode="targeted"`

Schema reference:
- `resources/project-gates-schema.md`

## Preflight Checks (required)
Before `plan` / `run`, verify the execution surface instead of discovering failures mid-run:

```bash
git status --short
test -f package.json && echo "PACKAGE_JSON_OK" || echo "PACKAGE_JSON_MISSING"
test -d _ctx/review_runs && ls -1dt _ctx/review_runs/run_* 2>/dev/null | head -n 3 || true
```

If statics are expected, verify runners before starting:
- biome: confirm `lint:biome` exists in `package.json`
- biome: confirm `biome.json` or `biome.jsonc` exists when the script expects repo config
- ruff: confirm `lint:ruff` exists in `package.json`
- ruff: confirm `pyproject.toml`, `ruff.toml`, or `.ruff.toml` exists
- pytest: confirm `uv` exists and target tests resolve

If any required preflight item fails, stop and report the blocker before `run`.

## Static Gate Readiness (required)
Do not assume lint scripts are wired correctly. Verify the commands and config surface explicitly:

```bash
jq -r '.scripts["lint:biome"] // "MISSING"' package.json
jq -r '.scripts["lint:ruff"] // "MISSING"' package.json
test -f biome.json -o -f biome.jsonc && echo "BIOME_CONFIG_OK" || echo "BIOME_CONFIG_MISSING"
test -f pyproject.toml -o -f ruff.toml -o -f .ruff.toml && echo "RUFF_CONFIG_OK" || echo "RUFF_CONFIG_MISSING"
```

If a required static command or config is missing, stop before `run` and report the exact gap. Do not wait for `UNKNOWN` or parser errors to discover it later.

## Canonical Flow
```bash
bun "$REVIEW_CLI" init --create
bun "$REVIEW_CLI" explore context
bun "$REVIEW_CLI" explore diff
bun "$REVIEW_CLI" plan --plan-path <path> || bun "$REVIEW_CLI" plan
bun "$REVIEW_CLI" run
```

Rules:
- `FOUND` and `AUTOGENERATED` are valid plan statuses.
- `MISSING` / `AMBIGUOUS` are non-blocking. Continue to `run`.
- If `run` explicitly refuses to continue because of plan resolution, rerun once with:
```bash
bun "$REVIEW_CLI" run --no-plan
```
- Treat `--no-plan` as a documented contingency, not the default path. Record why it was needed in the final report.

## Plan And Agent Contract (required)
After `plan`, verify that the run has a usable contract before continuing:

```bash
RUN_ID=$(ls -1dt _ctx/review_runs/run_* | head -n 1 | xargs basename)
test -f "_ctx/review_runs/${RUN_ID}/plan.json" && echo "PLAN_JSON_OK" || echo "PLAN_JSON_MISSING"
jq -r '.plan_status // "MISSING"' "_ctx/review_runs/${RUN_ID}/plan.json"
jq -r '.required_agents[]?' "_ctx/review_runs/${RUN_ID}/plan.json"
```

Rules:
- If `plan.json` is missing after `plan`, rerun `plan` once before `run`.
- If `required_agents` is empty but `plan_status` is `FOUND`, treat that as a blocker and report it.
- If `plan_status` is `AUTOGENERATED`, continue normally.
- Never assume agents were launched because `run` exited successfully; verify required agents from `plan.json` and final artifacts.

## Ingest Rules
Always use explicit flags:
```bash
bun "$REVIEW_CLI" ingest --agent <agent-name> --input <report.md>
bun "$REVIEW_CLI" ingest --static <tool> --input <output.md>
```

Never omit `--agent`/`--static` or `--input`.

## Static Gates (parser-conclusive)
### biome
```bash
bun run lint:biome > /tmp/biome-output.md 2>&1
```
Expected script behavior (`scripts/reviewctl/lint_biome_changed.sh`):
- changed files on `main...HEAD` for `js/ts/vue`
- excludes `litellm/.venv13`, `playwright-report`, `test-results`, `.mini-rag`
- empty scope fallback: minimal parseable check (`package.json`)

### ruff
```bash
bun run lint:ruff > /tmp/ruff-output.md 2>&1
```
Expected script behavior (`scripts/reviewctl/lint_ruff_changed.sh`):
- changed `.py` files on `main...HEAD`
- empty scope output includes `All checks passed!`

### pytest (targeted default)
```bash
cd apps/pae-api && uv run --python 3.13 --with pytest --with pytest-asyncio --with aiofiles \
  pytest -q tests/test_api/test_health.py tests/test_services/test_litellm_client.py tests/test_services/test_infrastructure.py \
  > /tmp/pytest-output.md 2>&1
```

Ingest statics:
```bash
bun "$REVIEW_CLI" ingest --static biome --input /tmp/biome-output.md
bun "$REVIEW_CLI" ingest --static ruff --input /tmp/ruff-output.md
bun "$REVIEW_CLI" ingest --static pytest --input /tmp/pytest-output.md
```

## Required Agents (avoid wrong-agent ingest)
Use the active run plan as contract:
```bash
RUN_ID=$(ls -1dt _ctx/review_runs/run_* | head -n 1 | xargs basename)
jq -r '.required_agents[]' "_ctx/review_runs/${RUN_ID}/plan.json"
```
Ingest only those agents as required. If ingesting extras, use `--extra`.

## Frontend Optional Gate
If `.reviewctl/project-gates.json` has `frontend.enabled=true`:
1. Run `frontend.vitest_command`
2. Run browser smoke via `frontend.runner`
3. Save evidence in `apps/pae-wizard/outputs/reviewctl/<run-id>-frontend-gate.md`

If browser agent is unavailable, record explicit `SKIP` and continue.
`frontend.blocking=false` means evidence-only.

## Debt Log (mandatory for limited scope)
When using changed-files/targeted scope:
- update `apps/pae-wizard/outputs/reviewctl/lint-debt-backlog.md`
- create/update `apps/pae-wizard/outputs/reviewctl/<run-id>-debt-log.md`

Must include: tool, top findings, paths, exclusion reason, date, run-id.

## Verdict and Consistency Check
Generate verdict:
```bash
bun "$REVIEW_CLI" verdict
```

Consistency check (required before reporting done):
```bash
RUN_ID=$(ls -1dt _ctx/review_runs/run_* | head -n 1 | xargs basename)
cat "_ctx/review_runs/${RUN_ID}/final.json"
```

Done criteria:
- verdict is `PASS` or `FAIL` (not `INCOMPLETE`)
- required statics are not `UNKNOWN`
- custom summary/handoff values match `final.json`

## Failure Handling
- Missing environment/dependency before `run`: stop and report the exact missing prerequisite.
- Missing or invalid `plan.json`: rerun `plan` once, then stop if the contract is still absent.
- Required agents absent from the run contract or final artifacts: stop and report which agents were not launched or not completed.
- `run` returns `INCOMPLETE`: inspect required agents/statics, ingest explicitly, rerun `verdict`.
- Static parser returns `UNKNOWN`: regenerate the tool output with the preferred command, re-ingest, rerun `verdict`.
- `biome`/`ruff` config error: fix the config/scope issue first or report the blocker; do not let the review silently degrade to `UNKNOWN`.
- Frontend runner unavailable: mark `SKIP`, keep the evidence, continue only if `frontend.blocking=false`.

## Mandatory Report to User
Always include:
- Run ID
- Final verdict (from `final.json`)
- Required static statuses
- Required agents completed/missing
- Frontend optional gate status (`PASS/FAIL/SKIP`, non-blocking)
- Debt log paths
- Artifact paths:
  - `_ctx/review_runs/<run-id>/final.json`
  - `_ctx/review_runs/<run-id>/final.md`
  - `apps/pae-wizard/outputs/reviewctl/<run-id>-summary.md`
- Whether preparation phase passed cleanly or required fallback/remediation
